1. Likelihood for the Multi-nomial Logit (MNL) Model

Suppose we have \(i=1,\ldots,n\) consumers who each select exactly one product \(j\) from a set of \(J\) products. The outcome variable is the identity of the product chosen \(y_i \in \{1, \ldots, J\}\) or equivalently a vector of \(J-1\) zeros and \(1\) one, where the \(1\) indicates the selected product. For example, if the third product was chosen out of 3 products, then either \(y=3\) or \(y=(0,0,1)\) depending on how we want to represent it. Suppose also that we have a vector of data on each product \(x_j\) (eg, brand, price, etc.).

We model the consumer’s decision as the selection of the product that provides the most utility, and we’ll specify the utility function as a linear function of the product characteristics:

\[ U_{ij} = x_j'\beta + \epsilon_{ij} \]

where \(\epsilon_{ij}\) is an i.i.d. extreme value error term.

The choice of the i.i.d. extreme value error term leads to a closed-form expression for the probability that consumer \(i\) chooses product \(j\):

\[ \mathbb{P}_i(j) = \frac{e^{x_j'\beta}}{\sum_{k=1}^Je^{x_k'\beta}} \]

For example, if there are 3 products, the probability that consumer \(i\) chooses product 3 is:

\[ \mathbb{P}_i(3) = \frac{e^{x_3'\beta}}{e^{x_1'\beta} + e^{x_2'\beta} + e^{x_3'\beta}} \]

A clever way to write the individual likelihood function for consumer \(i\) is the product of the \(J\) probabilities, each raised to the power of an indicator variable (\(\delta_{ij}\)) that indicates the chosen product:

\[ L_i(\beta) = \prod_{j=1}^J \mathbb{P}_i(j)^{\delta_{ij}} = \mathbb{P}_i(1)^{\delta_{i1}} \times \ldots \times \mathbb{P}_i(J)^{\delta_{iJ}}\]

Notice that if the consumer selected product \(j=3\), then \(\delta_{i3}=1\) while \(\delta_{i1}=\delta_{i2}=0\) and the likelihood is:

\[ L_i(\beta) = \mathbb{P}_i(1)^0 \times \mathbb{P}_i(2)^0 \times \mathbb{P}_i(3)^1 = \mathbb{P}_i(3) = \frac{e^{x_3'\beta}}{\sum_{k=1}^3e^{x_k'\beta}} \]

The joint likelihood (across all consumers) is the product of the \(n\) individual likelihoods:

\[ L_n(\beta) = \prod_{i=1}^n L_i(\beta) = \prod_{i=1}^n \prod_{j=1}^J \mathbb{P}_i(j)^{\delta_{ij}} \]

And the joint log-likelihood function is:

\[ \ell_n(\beta) = \sum_{i=1}^n \sum_{j=1}^J \delta_{ij} \log(\mathbb{P}_i(j)) \]

2. Simulate Conjoint Data

We will simulate data from a conjoint experiment about video content streaming services. We elect to simulate 100 respondents, each completing 10 choice tasks, where they choose from three alternatives per task. For simplicity, there is not a “no choice” option; each simulated respondent must select one of the 3 alternatives.

Each alternative is a hypothetical streaming offer consistent of three attributes: (1) brand is either Netflix, Amazon Prime, or Hulu; (2) ads can either be part of the experience, or it can be ad-free, and (3) price per month ranges from $4 to $32 in increments of $4.

The part-worths (ie, preference weights or beta parameters) for the attribute levels will be 1.0 for Netflix, 0.5 for Amazon Prime (with 0 for Hulu as the reference brand); -0.8 for included adverstisements (0 for ad-free); and -0.1*price so that utility to consumer \(i\) for hypothethical streaming service \(j\) is

\[ u_{ij} = (1 \times Netflix_j) + (0.5 \times Prime_j) + (-0.8*Ads_j) - 0.1\times Price_j + \varepsilon_{ij} \]

where the variables are binary indicators and \(\varepsilon\) is Type 1 Extreme Value (ie, Gumble) distributed.

The following code provides the simulation of the conjoint data.

Note 
# set seed for reproducibility
set.seed(123)

# define attributes
brand <- c("N", "P", "H") # Netflix, Prime, Hulu
ad <- c("Yes", "No")
price <- seq(8, 32, by=4)

# generate all possible profiles
profiles <- expand.grid(
    brand = brand,
    ad = ad,
    price = price
)
m <- nrow(profiles)

# assign part-worth utilities (true parameters)
b_util <- c(N = 1.0, P = 0.5, H = 0)
a_util <- c(Yes = -0.8, No = 0.0)
p_util <- function(p) -0.1 * p

# number of respondents, choice tasks, and alternatives per task
n_peeps <- 100
n_tasks <- 10
n_alts <- 3

# function to simulate one respondent’s data
sim_one <- function(id) {
  
    datlist <- list()
    
    # loop over choice tasks
    for (t in 1:n_tasks) {
        
        # randomly sample 3 alts (better practice would be to use a design)
        dat <- cbind(resp=id, task=t, profiles[sample(m, size=n_alts), ])
        
        # compute deterministic portion of utility
        dat$v <- b_util[dat$brand] + a_util[dat$ad] + p_util(dat$price) |> round(10)
        
        # add Gumbel noise (Type I extreme value)
        dat$e <- -log(-log(runif(n_alts)))
        dat$u <- dat$v + dat$e
        
        # identify chosen alternative
        dat$choice <- as.integer(dat$u == max(dat$u))
        
        # store task
        datlist[[t]] <- dat
    }
    
    # combine all tasks for one respondent
    do.call(rbind, datlist)
}

# simulate data for all respondents
conjoint_data <- do.call(rbind, lapply(1:n_peeps, sim_one))

# remove values unobservable to the researcher
conjoint_data <- conjoint_data[ , c("resp", "task", "brand", "ad", "price", "choice")]

# clean up
rm(list=setdiff(ls(), "conjoint_data"))

The fact that each task for each respondent has the same number of alternatives (3) helps. In addition, we need to convert the categorical variables for brand and ads into binary variables.

4. Estimation via Maximum Likelihood

We estimate the parameters of the MNL model using Maximum Likelihood. For each respondent-task combination, the probability of choosing an option is modeled using a softmax function over linear utilities. The utility is a function of product characteristics, and we estimate the parameters that maximize the likelihood of observed choices.

import pandas as pd
import numpy as np
from scipy.optimize import minimize

df = pd.read_csv("/home/jovyan/Desktop/mysite/projects/hw3/conjoint_data.csv")
df_encoded = pd.get_dummies(df, columns=['brand', 'ad'], drop_first=True)
df_encoded = df_encoded.sort_values(by=['resp', 'task']).reset_index(drop=True)

# Step 1: Extract features and ensure float type
X = df_encoded[['price', 'brand_N', 'brand_P', 'ad_Yes']].astype(float).values
y = df_encoded['choice'].astype(int).values

# Step 2: Reshape for MNL panel setup
n_alternatives = 3
n_tasks = int(len(y) / n_alternatives)

X = X.reshape((n_tasks, n_alternatives, -1))
y = y.reshape((n_tasks, n_alternatives))

# Step 3: MNL Log-likelihood
def mnl_log_likelihood(beta):
    beta = np.asarray(beta, dtype=float)
    utilities = np.einsum('ijk,k->ij', X, beta)  # X @ beta for each task
    exp_util = np.exp(utilities - np.max(utilities, axis=1, keepdims=True))  # stabilize
    probs = exp_util / exp_util.sum(axis=1, keepdims=True)
    chosen_probs = probs[y == 1]
    return -np.sum(np.log(chosen_probs + 1e-15))  # small constant to avoid log(0)

# Step 4: Estimate with MLE
init_beta = np.zeros(X.shape[2])
result = minimize(mnl_log_likelihood, init_beta, method='BFGS')
mle_estimates = result.x

5. Estimation via Bayesian Methods

import pandas as pd
import numpy as np
from scipy.optimize import minimize
# Bayesian estimation using Metropolis-Hastings MCMC with structured priors

# Prior standard deviations: [price, brand_N, brand_P, ad_Yes]
prior_sds = np.array([1.0, 5.0, 5.0, 5.0])

def log_prior(beta):
    return -0.5 * np.sum((beta / prior_sds) ** 2)

def log_likelihood(beta):
    beta = np.asarray(beta, dtype=float)
    utilities = np.einsum('ijk,k->ij', X, beta)
    exp_util = np.exp(utilities - np.max(utilities, axis=1, keepdims=True))
    probs = exp_util / exp_util.sum(axis=1, keepdims=True)
    chosen_probs = probs[y == 1]
    return np.sum(np.log(chosen_probs + 1e-15))

def log_posterior(beta):
    return log_likelihood(beta) + log_prior(beta)

# MCMC parameters
n_samples = 11000
burn_in = 1000
n_keep = n_samples - burn_in
n_params = X.shape[2]
samples = np.zeros((n_keep, n_params))
beta_current = np.zeros(n_params)
log_post_current = log_posterior(beta_current)

# Proposal SDs: [price, brand_N, brand_P, ad_Yes]
proposal_sds = np.array([0.005, 0.05, 0.05, 0.05])

accepts = 0
np.random.seed(42)

for step in range(n_samples):
    proposal = beta_current + np.random.normal(loc=0.0, scale=proposal_sds)
    log_post_proposal = log_posterior(proposal)

    log_accept_ratio = log_post_proposal - log_post_current
    if np.log(np.random.rand()) < log_accept_ratio:
        beta_current = proposal
        log_post_current = log_post_proposal
        if step >= burn_in:
            accepts += 1
    
    if step >= burn_in:
        samples[step - burn_in] = beta_current

accept_rate = accepts / n_keep

6. Discussion

Suppose we did not simulate the data, but instead received these estimates from a real-world conjoint survey. Here’s how we would interpret the results:

Observations from the Estimates

From both the Maximum Likelihood and Bayesian approaches, we observe the following patterns:

  • The coefficient on price is negative.
  • The coefficient for brand_N (Netflix) is greater than that for brand_P (Prime).
  • Each coefficient represents the marginal utility contribution of that feature, relative to the base level.

These estimates suggest meaningful consumer preferences, even in the absence of simulation context.

Interpreting ( {} > {} )

We used dummy coding where: - brand_N represents Netflix, - brand_P represents Prime, - and the base category (omitted) is Hulu.

So, when: [ {} > {} ] this implies that, holding all else constant (including price and ad exposure), consumers derive more utility from Netflix than from Prime. In practical terms, this means Netflix is more likely to be chosen than Prime when both appear as options.

A negative ( _{} ) reflects the basic economic principle that higher prices reduce utility, making consumers less likely to select that option. This aligns with standard expectations in consumer choice modeling.

Overall, the parameter estimates make sense and align with expected consumer behavior: people prefer lower prices, favor some brands over others, and possibly dislike ads (if that effect was also negative).

In this assignment, we estimated a standard Multinomial Logit (MNL) model, which assumes that all respondents share the same preferences — in other words, a fixed parameter ( ) across all individuals.

However, in real-world conjoint analysis, this assumption is often too simplistic. Consumers typically have heterogeneous preferences, and ignoring this variation can lead to misleading or overconfident conclusions.

Simulating Data from a Hierarchical (Multi-Level) Model

To simulate data from a multi-level (random parameter) model, we would:

  • Draw each respondent’s ( _i ) from a population-level distribution, such as: [ _i (, ) ] where ( ) and ( ) represent the mean and covariance of preferences across respondents.

  • Then, for each respondent ( i ), simulate their choices based on their own personalized ( i ), using the same MNL framework: [ P{ij} = ]

This introduces preference heterogeneity into the simulation.

Estimating a Hierarchical Model

To estimate this kind of model, we would need to: - Use Bayesian methods (like MCMC with Gibbs sampling or Hamiltonian Monte Carlo), or - Use frequentist approximations like Hierarchical Bayes, mixed logit (MIXL), or maximum simulated likelihood.

This involves: - Estimating both the population-level parameters (( , )) and - Inferring the individual-level ( _i )’s, often via partial pooling.

Why This Matters

Hierarchical models are preferred in practice because they: - Provide personalized insights (important for targeting and segmentation), - Account for variation in preferences, and - Avoid overstating the confidence in a “one-size-fits-all” estimate.

In short, to move from a standard MNL to a hierarchical model, you would simulate and estimate individual-specific coefficients, rather than a single shared coefficient vector.
